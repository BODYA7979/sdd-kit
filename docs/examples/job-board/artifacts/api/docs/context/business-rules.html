Hireboard business rules

The rules the system must enforce. Specs, tests and reviews cite them by ID. Rules are grouped by area and numbered with gaps (0x accounts, 1x postings, 2x profiles, 3x applications, 4x reviews), so a new rule never renumbers an old one.

Validated by: Maya Chen (product owner), 2026-10-19, from the draft in product-brief.md. A rule enters this file only after Maya has confirmed it. Anything else is an assumption, and write-spec's clarity gate treats it as one. To change a rule, ask Maya first, then update the specs that cite it.

Accounts (0x)

IDRuleEnforced inSince
BR-01Self-registration roles are candidate or employer. Requesting admin returns 422. Admins are seeded only.RegisterUserDTO validationHIRE-3
BR-02Employer registration creates exactly one company owned by that employer. The slug is Str::slug(company_name), with -2, -3 ... appended when taken.AuthService::register(), CompanyRepository::createForOwner()HIRE-3
BR-03Emails are unique, compared and stored lowercase.RegisterUserDTO, UserRepositoryHIRE-3
BR-04API tokens (Sanctum personal access tokens, name web) expire after 7 days. Logout revokes the current token.UserRepository::issueToken(), revokeToken()HIRE-3, ADR-0001, confirmed by Maya Chen 2026-10-20 (ADR-0001 sign-off)

Job postings (1x)

IDRuleEnforced inSince
BR-10Only open postings appear in search and detail. Draft and closed postings are never public (404 job_not_found).JobPostingRepository::searchOpen(), findOpenById()HIRE-1, fixed for detail in HIRE-9

BR-12Salary is optional, annual, in whole currency units with an ISO currency. When present, salary_min <= salary_max.not enforced in v1: no write path for postings until HIRE-11 (seeder and factory respect it)HIRE-1
