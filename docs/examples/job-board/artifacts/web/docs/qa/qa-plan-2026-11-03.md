No single spec covers this journey, so the acceptance criteria below were inferred from what the code does. Every criterion is marked **inferred** in the table because it did not come from a spec, and Maya Chen confirmed all nine on 2026-11-03 (Validate column). A failing case now means the code is wrong.

## Setup

```bash
# Terminal 1: API with demo data (local only)
cd ~/work/hireboard/api
php artisan migrate:fresh --seed
php artisan serve --port=8000

# Terminal 2: frontend
cd ~/work/hireboard/web
npm run dev        # http://localhost:3000
```

Look up the ids used in the cases below:

```bash
cd ~/work/hireboard/api
php artisan tinker --execute="echo App\Models\JobPosting::where('title', 'Legacy PHP Maintainer')->value('id');"   # CLOSED_ID
php artisan tinker --execute="echo App\Models\JobPosting::where('status', 'draft')->value('id');"                  # DRAFT_ID
php artisan tinker --execute="echo App\Models\JobPosting::where('status', 'open')->latest('published_at')->value('id');"  # OPEN_ID
```

All cases run as a guest (no `hireboard_session` cookie). Use a private browser window.

## Acceptance criteria

| ID | Criterion | Anchor | Inferred | Validate |
|----|-----------|--------|----------|----------|
| AC-1 | Search returns only `open` postings, newest `published_at` first. | BR-10, BR-11 | yes | confirmed 2026-11-03 |
| AC-2 | The filters `q`, `location`, `remote`, `employment_type` and `company` narrow the results and can be combined. | BR-11 | yes | confirmed 2026-11-03 |
| AC-3 | Search is paginated: `per_page` defaults to 20 and is capped at 50, and `meta` carries `current_page`, `per_page`, `total`, `last_page`. | BR-11, INV-01 | yes | confirmed 2026-11-03 |
| AC-4 | The `/jobs` URL is the filter state: filters are read from the query string, empty or unknown values are dropped, and the form writes the same query string back. | BR-11 | yes | confirmed 2026-11-03 |
| AC-5 | The job detail page shows an open posting with its company, and the company name links to `/companies/{slug}`. | BR-10 | yes | confirmed 2026-11-03 |
| AC-6 | An unknown, closed or draft posting id returns 404 `job_not_found` from the API, and `/jobs/{id}` renders the not-found page. | BR-10 | yes | confirmed 2026-11-03 |
| AC-7 | The careers page `/companies/{slug}` shows the company profile and its open postings. An unknown slug renders the not-found page. | BR-10 | yes | confirmed 2026-11-03 |
| AC-8 | The careers page shows the company's average rating and review count from the public reviews list, with a link to `/companies/{slug}/reviews`. | BR-42, BR-43 | yes | confirmed 2026-11-03 |
| AC-9 | A job card shows the salary as a yearly range in the posting currency (`€60,000 – €80,000 a year`). A posting with only one bound reads `From €X a year` (minimum only) or `Up to €X a year` (maximum only). A posting with no salary shows nothing. | BR-12, INV-07 | yes | confirmed 2026-11-03 |

Questions for validation (raised by the Criteria phase, not decided by the code) and Maya Chen's answers:

- AC-2: filters combine with AND. Is that the intended behavior, or should `q` also match the company name?
  - Answer (Maya Chen, 2026-11-03): AND is intended. `q` matches the posting only; searching by company is what the `company` filter is for.
- AC-3: a `per_page` above 50 is capped, not rejected with 422. Confirm that this is acceptable for API clients.
  - Answer (Maya Chen, 2026-11-03): capping is acceptable. No 422 for a large `per_page`.
- AC-9: `components/job-card.tsx` already formats one-sided ranges as `From …` and `Up to …`, and the demo seed has one (QA Engineer at Northwind Health, maximum only). Confirm that wording is the intended display.
  - Answer (Maya Chen, 2026-11-03): the wording is the intended display. Keep `From €X a year` and `Up to €X a year`.

## Out of scope

- Authenticated flows (applications, profiles, reviews submission and moderation) are covered by their own specs' manual tests.
- Employer publishing and closing postings ship with HIRE-11.
- Salary validation (`salary_min <= salary_max`) applies when postings are written, which is HIRE-11. The browse journey only reads salaries.
